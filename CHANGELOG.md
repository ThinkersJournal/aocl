# Changelog

## Unreleased (docs only, patch on 0.2.x; pm-assist allocates)

- **`aocl-rng-sys`: add the missing `NOTICE` to the package** (0.2.11 shipped without it) and fix the README: the 77 UPPERCASE `S/DRAND*` forms ARE declared (`GET_RNGVERSION` is stated by the guide but not exported, so it is not); the "added on demand" wording is gone. The NOTICE carries AMD's legal line (verbatim), says the repository's authors read the headers while the declarations were written by separate sessions that read only the guide, and names the measurements (integer width, user-generator protocol).
- **`aocl-math`: add the `NOTICE` its README already refers to** (it had none in the package).
- **tools:** `tools/check-package-files.py` lists what `cargo package` would ship and fails when a crate with a provenance statement lacks its NOTICE (run it before every first publish).

## 0.2.11 - 2026-11-27 (PM-allocated; patch on 0.2.x, the 0.2.x family number: FIX for the published broken static-link feature of aocl-sparse-sys and aocl-compression-sys)

- **FIX `aocl-sparse-sys` and `aocl-compression-sys`, feature `static-link` (Windows):** the feature asked the linker for libraries that do not exist in AOCL 6.0.68 (`aoclsparse-static` and `aocl_compression-static`; the install has `lib/LP64/static/aoclsparse.lib` and `lib/static/aocl_compression.lib`), so a `static-link` build failed with "could not find native static library". `static-link` now links `aoclsparse` / `aocl_compression` from the `static/` directory. Dynamic linking (the default) is unchanged. Measured with the lane's link-all tool, Windows 6.0.68: `aocl-compression-sys` static: 152 of 162 declared functions resolve (the 10 others are the LZMA-SDK helper names that no installed library exports); `aocl-sparse-sys` static: all 286 resolve, but the static library also needs the OpenMP runtime (`libiomp5md.lib`), which this crate does not link: add it to your link line (ROADMAP row 26). Linux static names are unmeasured.

## 0.2.10 - 2026-11-27 (PM-allocated; patch on 0.2.x, the 0.2.x family number: aocl-rng-sys clean-room declarations complete, aocl-securerng-sys tests only; the PM released it after reading the provenance changes)

- **`aocl-rng-sys`:** 78 UPPERCASE `S/DRAND*` forms are declared clean-room from AOCL API Guide 6.0 ch. 9.3 (`GET_RNGVERSION` is guide-stated but not exported by AOCL 6.0.68: not declared); the S callback typedefs are MEASURED; `srandinitializeuser`/`SRANDINITIALIZEUSER` and the D forms are declared but UNSAFE with an undocumented protocol (the UINI callback must set `state[0]=n` and `lstate>=n+3`; the guide does not state this), link-checked only, never called by a test. A link-all test checks every declaration. The provenance tables are `docs/cleanroom/README.md` and the per-set CSVs; the raw evidence is one archive under `docs/cleanroom/evidence/`.
- **`aocl-securerng-sys`:** tests only (`tests/securerng.rs`: link-all 15, width, constants against measured codes); the bindgen route, header-grant NOTICE, wrapper, bindings and the five `SECRNG_*` constants are as in published 0.2.5.
- Nothing here changes a published API of a crate released at 0.2.x; the RNG crates have no real release before this one.

## 0.2.0 - 2026-11-23 (BREAKING for `aocl-sparse`, allocated by pm-assist)

- Stale-DLL-on-PATH guard (pm-kernels notice 2026-11-22): new Windows-only `aocl_build::loaded_dll` (`resolve_loaded_dll`, `assert_loaded_under`; additive) and `crates/aocl-build/tests/loaded_dll.rs`: one test per component family (blas, lapack, compression, crypto, data-analytics, fft, math, rng, scalapack, securerng, sparse, utils) loads each linked DLL by name through the loader's own search, prints the `GetModuleFileNameW` path, and fails by name if it is not under `AOCL_ROOT`; control `control_wrong_dir_first_on_path_fails_by_name` (a copy in a temp dir first on PATH) is rejected. 13/13 pass with the HANDOFF PATH. Measured: `amdsecrng.dll` resolves to `amd-rng/lib/LP64` (both dirs ship it), still under the root. Not covered: the Intel runtime DLLs (libiomp5md etc.) live outside `AOCL_ROOT`; no expected dir is named for them yet. The test resolves by name with LoadLibraryW, it does not inspect the modules of a linked test binary.
- Licence texts (facts and package lists: ROADMAP row 1): the published 0.1.0 crates contain no licence or notice file (not even MIT/Apache; verified by downloading five of them). `LICENSE-MIT` and `LICENSE-APACHE` are now in every crate directory, and `NOTICE` files (verbatim header notices, generated from the header include closure of each `wrapper/*.h`) in the nine `*-sys` crates whose headers carry or have a project notice; `aocl-math-sys` and `aocl-rng-sys` (publish held) have none. - New `THIRD-PARTY-NOTICES.md`: origin and licence of everything derived from AMD or other third parties (the 11 generated bindings files and their source headers, the `lz4frame.h` guard, test data), what was verified, and 5 open licence questions for the owner (`amdlibm.h` carries an object-code-only AMD licence, `rng.h` has no licence grant, the AOCL for Windows EULA, `blis.h`/`cblas.h`/`lapack.h` carry no notice, FFTW is GPL). All 11 bindings files now start with a pointer comment to it.
- Version evidence (read on the test box 2026-11-22): the 11 component `ReleaseNotes.txt` files under `AOCL-Windows` that name a version all say 5.3.0 (blis, libflame, compression, crypto, da, fftz, libm, rng, scalapack, securerng, sparse; fftw and utils name none); the generated `AOCLSPARSE_VERSION_*` constants are 5.3.0; the installer's registry entry (`AMD AOCL Windows`) has DisplayVersion 5.3.514. Nothing read says 5.3.2, which earlier notes here used without a source, so every claim now says `5.3.x`.
- `aocl-sparse`: **breaking, and it did not compile before on AOCL 5.3.** `csr2bsr_f64` / `csr2bsr_f32` now take a `block_order: Order` argument after `descr`, because `aoclsparse_dcsr2bsr` / `scsr2bsr` in the AOCL 5.3.x headers have a `block_order` parameter (the call had 10 arguments, the header has 11: error E0061 against regenerated bindings). New test `csr2bsr_block_order_f64_and_f32` checks both orders and both precisions. The vendored docs.rs bindings for `aocl-sparse-sys` are AOCL-sparse 5.1.0 (their `AOCLSPARSE_VERSION_*` constants) and still have the 10-argument form, so docs.rs builds of `aocl-sparse` will not compile until they are regenerated (ROADMAP row 5).
- `aocl-scalapack`: new `tests/grid2d_mpi.rs`: true 2D block-cyclic grids (1x1, 2x1, 3x1, 2x2, 2x3 on 1, 2, 3, 4, 6 ranks) and three right-hand sides (the last column block short): `pdgesv`, `pdgemm` (N, T), `pdgetrf`+`pdgetrs` (N, T), `pdpotrf`+`pdpotrs` (both triangles), `pzgesv`, `pcgesv`, plus a `pdgesv` whose first block is owned by process (1 % pr, 1 % pc), i.e. non-zero RSRC/CSRC. Mutants that stay equivalent, measured: passing A's descriptor for B in `pdgesv` / `pcgesv` (an N x N and an N x 3 descriptor with the same blocking, grid and leading dimension deal the first three columns identically; the global column count only feeds argument checks), at nrhs = 3 on 2x2.

Fix: every integer in both crates is a new `pub type Int` (`i32`, or `i64` with `ilp64`; the BLACS C entry points take the same width, measured), so the LP64 API is unchanged. Measured: the unit test and `pdgesv_mpi`, `psgesv_mpi`, `complex_mpi` (1-3 ranks) and `grid2d_mpi` (1, 2, 3, 4, 6 ranks) pass under ILP64 and under LP64.) The paragraph below was written first, when the feature was only refused with a `compile_error!`.

- `aocl-scalapack`: `tests/pdgesv_mpi.rs` also checks `pdgemm` (`Trans::No` with alpha 2 / beta 0.5, and `Trans::T`) against a serial product on 1, 2 and 3 ranks (run by hand 2026-11-22); mutants `Trans::T`->`N` and `alpha*2` fail it on every rank count. - `aocl-compression-sys`: **did not build against AOCL 5.3.x** (bindgen: `lz4frame.h` not found; the Windows install ships `lz4.h` and `lz4hc.h` but no `lz4frame.h`). `wrapper/compression.h` now includes it only if `__has_include(<lz4frame.h>)`, so installs that ship it keep the `LZ4F_*` bindings and the safe crate (which uses none) builds on 5.3.x. `aocl-compression`: 13 tests pass; new tests check the format each `Codec` produces (zstd magic, zlib header, bzip2 `BZh`, snappy length preamble) and decode a zlib stream made by Python's `zlib`, because the round-trip tests used one mapping in both directions and could not see a wrong codec id; three mutants (Zlib->Zstd id, Snappy->LZ4 id, LZ4 source size minus one) fail them.
- `aocl`: new `tests/reexports.rs` (one test per feature, 13 with all features): each module must be the component it names. A mutant re-exporting `aocl_blas` as `math` fails to compile the test.
- Vendored docs.rs bindings regenerated from AOCL 5.3.x (bindgen 0.73.2, AMD headers; was bindgen 0.69.5 against older headers) for `aocl-sparse-sys`, `aocl-crypto-sys` and `aocl-data-analytics-sys`: required, because with the old files the three wrappers above no longer compile in `DOCS_RS=1` mode (docs.rs builds the wrapper crates against the vendored files; measured: 2, 9 and 29 errors before, 0 after). `DOCS_RS=1 cargo check` of the whole workspace passes (measured with `CARGO_BUILD_BUILD_DIR` overridden: the user cargo config redirects `build-dir`, so `CARGO_TARGET_DIR` alone reuses stale build scripts and reports a false pass). - `aocl-crypto`: **did not compile against AOCL 5.3.x; now does** (public API unchanged). Constants `_alc_cipher_mode_*`, `_alc_digest_mode_*`, `_alc_mac_type_*`, `alc_rng_*_t_*` are now `alc_cipher_mode_*` etc.; `alcp_cipher_encrypt/decrypt` and `alcp_cipher_aead_encrypt/decrypt` take an `outlen` pointer; two `bool` arguments. **Behaviour change fixed:** in 5.3 `alcp_cipher_aead_get_tag` on decryption compares the buffer you pass with the computed tag and returns `ALC_ERROR_TAG_MISMATCH` (14), so `Aead::verify_and_decrypt` (which passed a zeroed buffer) rejected every valid GCM message (a defect in the rejecting direction: new test `aes_gcm_every_tag_bit_flip_rejected` checked that all 128 single-bit flips of a tag are still rejected with the plaintext zeroed, and the unmodified tag is accepted); it now passes the expected tag, treats 14 as the tag-mismatch error, and still compares afterwards for older versions. 22/22 tests pass; mutants (mismatch check disabled; SHA2-256 mapped to SHA2-384) fail them.
