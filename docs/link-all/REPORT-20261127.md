# Link-all over every `aocl-*-sys` crate against the installed AOCL 6.0.68 (Windows 11, x86_64), 2026-11-27

**Method** (`tools/link-all-crates.py`): build each crate (bindgen as usual), take the address of EVERY `pub fn` of the bindings it generated in a throw-away test, link; link.exe lists every unresolved symbol; each is classified against `dumpbin /exports` of EVERY AOCL DLL. **Controls in every row:** a made-up symbol must fail to link and be reported (negative; PASS everywhere); the same test minus the unresolved names must link (positive; PASS for every dynamic row; FAILS for static rows that need libraries the crate does not link: stated below). Data: `results-20261127.json.gz` (before and after the fixes, per row: declared, resolved, unresolved + class); `known-unresolved.json.gz` (what `--strict` tolerates). Windows only; **Linux unmeasured**. The safe wrappers reference none of the left-out names (grep, control: they reference the resolved ones).

## Classes (the PM's rulings, 2026-11-27)
exported by NO installed library, dynamic or static -> default-OFF `header-only-unexported`, never deleted; exported by ANOTHER DLL -> a default-OFF feature that links it, measured; static-only -> `cfg(static-link)`.

## Static (`static-link`) findings
The `static-link` feature of `aocl-sparse-sys` and `aocl-compression-sys` did not BUILD (wrong library names; fixed in #25). Static builds that need more on the link line than the crates link (documented in each README, ROADMAP row 26; positive control fails without them): sparse, blas, lapack (OpenMP runtime `libiomp5md`; lapack also static BLIS), crypto (`bcrypt` + OpenSSL libcrypto), data-analytics (oneAPI Fortran runtime, OpenMP, BLAS/LAPACK). fft, utils, compression static builds need nothing extra.
